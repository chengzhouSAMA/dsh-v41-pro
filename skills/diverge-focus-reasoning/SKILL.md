# 发散—聚焦推理

## 为什么这样做
顺着一条思路硬推，一旦方向错了，后面全部白费。先把问题打开（发散），再把每一块单独做深（聚焦），最后拼回去并检查（汇聚），就能更早发现错误，也更容易看出结论之间的矛盾。

## 什么时候用
- 用：需要多步推理、有多个约束或多种可能思路、一时想不清楚的问题；用户明确要求这种方式时，无论难易都用
- 不用：事实问答、闲聊、一两步就能答的问题。直接回答

## 流程
按顺序执行，每个阶段用下面的标题输出。思考时也沿用这个顺序，不要另起一套。

### 阶段0 理解
- 用一句话写出目标
- 列出已知条件、约束、要求的未知量
- 题目有歧义时，选最合理的理解，并写明这个假设

### 阶段1 发散（只拆问题，不求解，不下结论）
1. 换几个角度看问题，至少用3个：正向推进、从结论倒推、特例与极端情况、分类讨论、类比相似问题、检查隐含条件和陷阱
2. 不加筛选，先列出候选子问题，至少6个
3. 合并重复、删掉无关的，保留3到7个，编号为 Q1…Qn
4. 每个 Qk 写清三项：目标（要得到什么）｜输入（来自题目，或来自哪个 Qj 的结论）｜依赖（要先做哪些）
5. 自检：这些子问题合起来能覆盖原问题吗？有没有漏掉的条件？

### 阶段2 聚焦（按依赖顺序，一次只做一个模块）
每个模块用同样的格式：

【Qk】
- 子问题：用一句话重述，只带入必要的输入
- 推理：分步写，每步说明依据
- 结论：一句话
- 验证：换一种方法重算、代回检验、估算数量级，选一种
- 置信度：高 / 中 / 低

规则：
- 做这个模块时，不去讨论其他子问题，这样思路才能集中
- 后面的模块只引用前面模块的"结论"，不重复它们的推导
- 验证没通过或置信度为低时，换一种方法重做一次；仍不行就标记"待定"，写明卡在哪里，交给阶段3处理。每个模块最多重做1次

### 阶段3 汇聚
1. 按依赖关系，把各模块结论拼成完整解答
2. 冲突检查：任意两个结论矛盾时，回到相关模块找原因并修正（整体最多回溯2次）
3. 对照阶段0的目标和约束，逐条核对
4. 用特例、反例或代回，再验证一次最终答案

### 阶段4 回答
- 先给最终结论，再给精简的关键推导，不要把前面的过程全部重复
- 明确说出仍然不确定的地方和原因

## 原则
- 子问题的数量跟着难度走，不要为了凑数硬拆
- 不编造数据、公式或引用；不确定就直说
- 每个阶段保持简洁，不写空话
- 用户只要答案时，隐藏过程，只给结论和关键依据
